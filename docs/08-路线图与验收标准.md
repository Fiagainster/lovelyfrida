# 08 · 路线图与验收标准

> 验收不写"功能已实现"，写**「用哪个真实任务验」**。因为真实任务才是唯一不会骗人的标准。

## 二、逐里程碑

### M0 · 看得见

| 项 | 内容 |
|---|---|
| 交付 | ① Tauri 应用骨架（单 exe 可启动）② 流水线视图（节点 + 状态灯 + 展开逐条检查项）③ 环境体检（10 项）④ adb 连接（含 15s 硬超时与 offline 自愈）⑤ `Workspace Guard`（只读根 + 拒绝写）⑥ 审计日志 |

| 验收 | **U1 + U7** |
| 退出条件 | 从零启动到"设备已连接"全绿，且每个绿灯都能点开看到判定依据 |

### M1 · 连得上

| 项 | 内容 |
|---|---|
| 交付 | ① `FridaBackend` 三通道 + 自动切换 ② 版本三处联动检查 + 自动推送匹配版 ③ 会话托管（后台常驻 + 断连自动恢复）④ 进程列表（系统进程与用户应用分组）⑤ 原始终端（xterm.js）⑥ Recorder（Step 记录 + 导出 PS/bash） |

| 验收 | **U1 后半段**（杀掉模拟器再开，自动恢复）+ 终端里手敲命令能被录成 Step |
| 退出条件 | 用户全程不碰终端即可完成"连接 → attach → 注入空 agent 收到 hello" |

### M2 · 挂得上

| 项 | 内容 |
|---|---|
| 交付 | ① 探针工作台（声明式表单 + 7 个内置模板）② agent 代码生成（自动处理 overloads / `$init` / 延迟注册 / try-catch 三态 / byte[] hex / 截断）③ 结构化 Trace 落 `.jsonl` + 时间轴视图 ④ 诊断引擎 v1（E / S / P 三组共 23 条规则） |
| 关键难点 | P-05 时序（替代手写 `setTimeout`）；O-02 高频事件不卡 UI（事件分层 + 虚拟滚动） |
| 验收 | **U2**（APK-1 的挂钩，全程零 JS）+ **U3 前置**（能看到"装载 3 个探针 / 命中 0 次"并弹出 O-03 诊断卡） |
| 退出条件 | 用模板填表即可拿到 `IN='Abc123456'‖'etmLYLvSIJn2mzgC'` 这类结构化入参 |

### M3 · 问得出来

| 项 | 内容 |
|---|---|
| 交付 | ① 数据回灌向导（七步 + 逐条状态灯 + md5 校验 + 登录态预警）② 受控实验台（变量/通道/输入组）③ 差分矩阵（变异度自动排序 + 结论候选含被否证假说） |
| 关键难点 | 矩阵的"结论候选"要给**多假设**而不是单答案；D-07 的登录态预警要与 O-03 联动 |
| 验收 | **U3 + U6** |
| 退出条件 | APK-15 的 `[1:-2]` 规则在 UI 里得出，且"削 2 个尾字符"这一假说被显式否证 |

### M4 · 算得出来

| 项 | 内容 |
|---|---|
| 交付 | ① 算法还原（分层穷举 + 规格书输出 + 逐字节自证）② 爆破编排（候选空间估算 + hashcat 命令生成 / 专用骨架生成）③ **强制自测桩**（不通过不允许全量跑）④ 进度可视化 + 命中反向校验 |
| 关键难点 | C-07：把"自测"做成硬门槛；生成的 C 骨架要含链式轮优化（预置填充块 + `SHA256_Transform`） |
| 验收 | **U4 + U5**（迭代 10000、爆破命中 593476） |
| 退出条件 | 从（明文, salt, 目标值）出发，不写代码，一路走到 HIT，且两条自证都过 |

### M5 · 交得出去

| 项 | 内容 |
|---|---|
| 交付 | ① 档案台账（含 `confidence=high` 必须双证据的**数据库约束**）② Obsidian 导出（带截图位）③ 案卷包（可交接）④ 诊断库补全（O / D / C / X 四组共 25 条） |
| 关键难点 | 导出形态要直接可用（不能是"半成品 markdown"） |
| 验收 | **U8 + U10** |
| 退出条件 | 另一个人拿到案卷包，能按里面的命令从头复现主要结论 |

## 三、验收用例（真实任务，10 条）

**这是本文档最重要的部分。** 每条都来自已经发生过的工作，因此不会变成"理想化测试"。

| # | 用例 | 对应真实任务 | 通过标准 | 里程碑 |
|:--:|---|---|---|:--:|
| **U1** | 连上端口未知的模拟器 | MUMU 12，端口 16384/16385/7555 不确定 | 不查任何文档、不问人，工具自己找到并连上；失败时列出试过的端口与各自结果 | M0/M1 |
| **U2** | 挂钩拿到方法入参 | APK-1（notevault `AESUtil.hashPassword`） | 填表 + 选模板完成，**零行 JS**；时间轴上看到 `IN='Abc123456'‖'etmLYLvSIJn2mzgC'` | M2 |
| **U3** | 受控实验反推变换规则 | APK-15（`password.json` → SQLCipher 口令） | 差分矩阵得出 `[1:-2]`，并列出被否证的假说；追加一组输入可继续验证 | M3 |
| **U4** | 反推 KDF 并定死迭代数 | APK-18 | 输出 `h₁=SHA256(pw‖salt)`、链式 hex、迭代 **10000**；自证与库值逐字节相等 | M4 |
| **U5** | 生成专用爆破器并命中 | APK-19 | 自动识别"hashcat 无此模式"→ 生成 C 骨架 → 自测通过 → 跑出 `HIT 593476` → 反向校验一致 | M4 |
| **U6** | 数据回灌一次成功 | 两个 App 的私有目录回灌 | 七步全绿；uid 自动取（10042/10043）；md5 逐文件一致；有登录态时给出预警 | M3 |
| **U7** | 只读保护生效 | 沿用既有事故（漏 `:ro` 改动检材） | 尝试对检材路径写入 → **被直接拒绝**（不是弹窗确认）；审计日志留痕 | M0 |
| **U8** | 一键导出给笔记系统 | 本轮笔记写作 | 导出 markdown 含命令 + 输出 + 与笔记对齐的`【截图位 N-x】`编号，直接可粘 | M5 |
| **U9** | 换 App 复用档案 | 从 notevault 换到 hidden.calculator | 只改 `AppProfile` 的差异字段（包名/uid/数据目录/口令文件/入口手势）即可开跑，不需重走一遍探索 | M2 |
| **U10** | 案卷包交接 | 模拟"另一个人接手" | 拿到包的人不看原会话，按包内命令复现主要结论 | M5 |

**U9 和 U10 是"产品化程度"的真正标尺**：前者验知识能否沉淀，后者验成果能否交付。

## 四、非功能验收

| 项 | 标准 | 状态 |
|---|---|---|
| 启动 | 冷启动到可操作 ≤ 3s（不含设备连接） | ✓（首启自检 + 快速体检 1.3~3.5s 出全结果） |
| 内存 | 常驻 ≤ 300 MB；观测 10 万事件后增量 ≤ 200 MB | 待实测 |
| 响应 | 事件速率 5000/s 时 UI 仍可交互（不卡滚动） | ✓（2026-10 真机压测：批量路径（生产 probe_hit）5014 事件/s 落盘零丢失、CDP 往返 14~40ms、时间轴可切可滚；未批量最坏情况（console 逐条直发）上限 ~1154 事件/s 且有一次 ~7s 停顿——批量层是达标前提；脚本 scripts/it_stress_events.py） |
| 离线 | 全功能离线可用；网络抓包验证零外联 | ✓（C1 按需下载为 opt-in 显式联网，不破坏默认零外联） |
| 分发 | 单安装包，无需用户预装 adb / frida / Python | ✓（NSIS 随包全量；瘦身构建 opt-in） |
| 稳健 | 任一外部进程被杀（adb / frida-server / sidecar）后，30s 内自动恢复或明确报错，不静默 | ✓（联调实测：sidecar 击杀 → 前端明确感知 → 重新附加自愈；frida-server 死亡 → S-03 诊断卡 + 会话失败明示；trace_gap 证据留痕） |
| 可审计 | 审计日志覆盖 100% 的写操作与明文揭示动作 | ✓（哈希链 + 轮转 + 全写路径 guard） |

## 五、风险登记

| # | 风险 | 影响 | 缓解 |
|:--:|---|---|---|
| R1 | **通道 A 的 `frida` crate 版本滞后** | 默认通道不可用 | 三通道设计本身就是缓解；把通道选择做成配置项 |
| R2 | frida 17.x 时序变化导致探针注册失败 | 挂钩大面积失效 | 自动延迟注册 + 失败重试 + 三态上报（P-05 / P-06） |
| R3 | 反调试 App 无法 hook | 部分目标做不了 | 明确报因（P-08），不承诺解决；加强静态分析侧的配合 |
| R4 | 高频事件把 UI 拖死 | 工具本身成为瓶颈 | 事件分层（L1/L2/L3）+ 虚拟滚动 + 原始输出按需拉取 |
| R5 | 差分矩阵给出过度泛化的结论 | 结论错误 | 强制"多假设 + 被否证项"，且必须人工确认（原则 5） |
| R6 | 生成的自写爆破器实现不等价 | 白跑几小时 | 强制自测桩（C-07），不过不允许全量 |
| R7 | 只读保护被绕过（用户手工在别的工具里改检材） | 检材被破坏 | 工具外无法阻止；但"写前校验数据指纹"能发现并拒绝继续 |
| R8 | 只有一个开发者 + 大量模块 | scope 蔓延 | 里程碑强绑定验收用例；M0~M2 是必做，M3~M5 可分期 |

## 六、待决策项（需要你拍板）

设计文档里凡是"我做了选择但存在合理替代"的地方，都列在这里。**在开工前定掉，比实现到一半改便宜得多。**

| # | 决策点 | 我的建议 | 备选 |
|:--:|---|---|---|
| D1 | 前端框架 | **Vue 3 + Vite**（上手成本低，够用） | React（生态更大） |
| D2 | 主通道 | **通道 B（Python sidecar）优先**，通道 A 作为后续优化 | 通道 A 优先（单 exe 更干净，但构建重、版本耦合紧） |
| D3 | native 层支持深度 | **只做"按符号挂导出函数 + 读参数"**，不做反汇编 | 深度（接 Ghidra/radare2）—— 成本高，且与现有静态能力重叠 |
| D4 | 设备支持范围 | 先只做 **MUMU 12 (x86_64)**，留 arm64 接口 | 一开始就支持真机 + 其它模拟器（夜神/雷电） |
| D5 | 多设备并行 | **不做** | 做（复杂度高，单机取证用不上） |
| D6 | 与 `apk-inspect` 的打通 | **做（优先级高）**：导入符号清单 + 导出 Finding | 不做（各自独立） |
| D7 | 导出默认脱敏 | **默认脱敏**（有审计的"揭示"入口） | 默认明文（方便，但风险高） |
| D8 | 是否内置"案例库/题库" | **不做**（与取证工具定位不符，也易越界） | 做（对 CTF 教学方便） |

## 七、开工前的三件事

在写第一行代码之前，必须先做完：

| # | 事 | 为什么 |
|:--:|---|---|
| 1 | **D1~D8 拍板** | 尤其 D2（影响整个后端架构）与 D6（影响接口设计） |
| 2 | **把 U1~U10 手工再走一遍并录屏** | 验收用例必须先在命令行里被验证过，否则工具会照着"想象的流程"实现 |
| 3 | **整理一份二进制清单** | adb / frida-server 各版本、来源、sha256（07 章的供应链要求） |

第 2 条尤其重要：**这份文档里的流程全部来自已经走过的路，不是设计出来的路。** 实现时如果发现某个流程在真实环境里跑不通，那一定是文档错了 —— 以真实环境为准。
