# 06 · 数据模型与存储

> 目标：让一次动态分析的**全部过程**都能被存档、被别人接手、被当作回归测试集。

---

## 一、实体总览（15 个）

```
Case ──┬── Device ──┐
       │            ├── Target ── Session ──┬── Probe
       ├── AppProfile ┘                     ├── Run ── TraceEvent
       │                                    └── Step（录制）
       ├── Experiment ── ExperimentCase ── DiffResult
       ├── CryptoScheme
       ├── BruteJob
       ├── Finding
       └── Artifact
```

| # | 实体 | 一句话 |
|:--:|---|---|
| 1 | `Case` | 一个案子（一次比赛 / 一个委托） |
| 2 | `Device` | 一台设备（模拟器/真机）+ 连接方式 |
| 3 | `AppProfile` | 一个应用的分析档案（包名/uid/数据目录/口令文件/入口手势） |
| 4 | `Target` | **设备 × 应用 × 数据版本** 的绑定 |
| 5 | `Session` | 目标与一组探针的一次绑定 |
| 6 | `Probe` | 声明式探针定义 |
| 7 | `Run` | 会话的一次执行 |
| 8 | `TraceEvent` | 一条结构化调用记录 |
| 9 | `Step` | 一次可重放的操作（录制单元） |
| 10 | `Experiment` | 一次受控实验 |
| 11 | `ExperimentCase` | 实验里的一组输入 |
| 12 | `DiffResult` | 差分矩阵的计算结果与结论候选 |
| 13 | `CryptoScheme` | 反推出的算法规格书 |
| 14 | `BruteJob` | 一次枚举任务 |
| 15 | `Finding` | 一条结论（题号/答案/置信度/证据） |
| 16 | `Artifact` | 产物（截图/日志/导出文件） |

（16 个，其中 `Step` 挂在 `Run` 下。）

---

## 二、关键实体字段

### 1 · Case

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 文本 | 短标识，如 `pgs-2026` |
| name | 文本 | 展示名 |
| root_case_dir | 路径 | 案子的工作区根 |
| read_only_roots | 路径列表 | ★ **检材只读根**（工具据此拒绝写入） |
| created_at / updated_at | 时间 | |

### 2 · Device

| 字段 | 说明 |
|---|---|
| serial | `127.0.0.1:16385` 之类 |
| adb_path | 实际使用的 adb 可执行文件路径（含版本） |
| port_candidates | 试过的端口与结果（E-02 留痕） |
| abi / android_version / is_root / selinux | 体检结论 |
| frida_server_version_installed | 设备端当前版本 |

### 3 · AppProfile

| 字段 | 说明 |
|---|---|
| package | `com.notevault.app` |
| uid | `10042`（实测值，不是推断） |
| apk_path | 检材内 APK 路径（只读） |
| data_dirs | 需要回灌的目录清单（相对包目录） |
| secret_files | 口令/密钥文件位置清单（可多个，带优先级） |
| secret_transform | 变换规则（如 `[1:-2]`，可为空） |
| entry_gesture | 入口手势（`long_press` / 坐标 / 时长） |
| entry_coords | 坐标表（分辨率绑定，如 1080×1920） |
| notes | 备注 |

**这个实体是"知识资产"** —— 第二个同类 App 出现时，档案就是起点。

### 4 · Target

| 字段 | 说明 |
|---|---|
| device_id / app_profile_id | 组合键 |
| data_version | 数据版本指纹（源目录的哈希或时间戳） |
| injected_at | 回灌时刻 |
| integrity | 回灌后校验结论（逐文件 md5） |

### 6 · Probe

| 字段 | 说明 |
|---|---|
| name | 展示名 |
| clazz | 目标类 |
| method | 目标方法（`$init` 表示构造函数） |
| overload_policy | 全部 / 指定签名 |
| arg_formatters | 每个参数的格式化器（数组，与参数位置对应） |
| max_len | 截断上限 |
| condition | 命中条件（无条件 / 参数正则 / 返回正则） |
| action | `log` / `pause` / `modify_arg` / `modify_ret` / `snapshot` / `write_file` |
| on_class_missing | `skip` / `fail` |
| state | 已装载 / 类缺失 / 挂载失败 / 未装载 |
| hits | 命中计数 |

### 8 · TraceEvent

| 字段 | 说明 |
|---|---|
| run_id / probe_id | 归属 |
| seq | 递增序号（用于排序与去重） |
| ts_mono / ts_wall | 单调时间（算耗时）+ 墙钟时间（对齐截图） |
| kind | `HOOK` / `ARG` / `FIELD` / `NATIVE` / `ERROR` / `CUSTOM` |
| thread | 线程标识 |
| args | 结构化数组（每个元素带类型标签） |
| ret | 结构化（含类型标签） |
| duration_us | 耗时 |
| truncated | 是否被截断及其完整长度 |

**类型标签是必须的**：`byte[]` 与 `String` 不能混为一谈 —— 差分矩阵和算法还原都依赖类型。

### 10/11/12 · Experiment / Case / DiffResult

**Experiment**

| 字段 | 说明 |
|---|---|
| name / 描述 | |
| variable_kind | `file_content` / `ui_input` / `method_arg` |
| variable_target | 具体目标（哪个文件 / 哪个框 / 哪个方法第几个参数） |
| channels | 观测通道列表（每个通道如何读取） |
| expected_answer_space | 已知答案空间（如"长度 4-18 的字符串"） |

**ExperimentCase（一组输入）**

| 字段 | 说明 |
|---|---|
| value | 实际取值 |
| origin | `manual`（▶）/ `generated`（▷） |
| note | 为什么设计这一组 |

**DiffResult**

| 字段 | 说明 |
|---|---|
| matrix | 行=输入组，列=通道 |
| variance | 每列的变异度与排序 |
| hypotheses | 结论候选列表（含**被否证的**） |
| confirmed | 人工确认状态 |

### 13 · CryptoScheme

| 字段 | 说明 |
|---|---|
| family | SHA-256 / MD5 / PBKDF2-… |
| concat_order | `pw‖salt` / `salt‖pw` / `pw` |
| salt_form | raw / base64_text / hex_concat |
| per_round_input | digest / hex_digest |
| iteration | 迭代次数（如 10000） |
| output_encoding | hex / base64 |
| self_test_passed | 自证是否通过（原则 5 第一条证据） |
| real_device_passed | 真机是否通过（第二条证据） |
| evidence_refs | 支撑该规格书的 TraceEvent / 实验 id |

### 14 · BruteJob

| 字段 | 说明 |
|---|---|
| scheme_id | 依据哪份规格书 |
| space | 掩码 / 字典 / 规则 / 混合 |
| candidates_total / speed / eta | 预估三件套 |
| engine | `hashcat` / `builtin_c`（含生成骨架的路径） |
| self_test_passed | ★ 自测是否通过（C-07：不过不允许全量跑） |
| status | 待跑 / 跑中 / 命中 / 完成无果 / 中断 |
| hit_value | 命中值（若有） |
| reversed_verified | 反向校验（用命中值重算目标，是否一致） |
| perf_note | 性能对照记录（如 200 → 2400 候选/秒） |

### 15 · Finding

| 字段 | 说明 |
|---|---|
| question_id | 题号（如 `APK-15`） |
| question | 问题原文 |
| answer | 答案 |
| confidence | `high`（双证据）/ `medium`（单证据）/ `low`（推断） |
| evidence | `math` / `device` / 两者都记 |
| source | 出处（哪个实验/任务/探针） |
| artifact_ids | 关联产物（截图等） |
| screenshot_slot | 截图位编号（与笔记 `【截图位 N-x】` 对齐） |

**约束**：`confidence=high` 必须同时有 `math` 与 `device` 两条证据，否则不允许保存 —— 把原则 5 变成数据库约束，而不是文档里的一句话。

### 16 · Artifact

| 字段 | 说明 |
|---|---|
| kind | `screenshot` / `log` / `export` / `binary` |
| path | 相对 `cases\<id>\artifacts\` 的路径 |
| sha256 | 完整性 |
| created_by | 哪个动作产生（可回溯到 Step） |

## 三、磁盘布局

```
D:\Project\lovelyfrida\
│
├── bin\                                  # 内置二进制（随程序升级）
│   ├── adb\windows-x64\adb.exe
│   └── frida-server\16.7.19\android-x86_64\
│                    16.7.19\android-arm64\
│                    17.x.y\…
│
├── workspace\                            # ★ 唯一可写区
│   └── <case>\<pkg>\
│       ├── source\                       # 从检材复制来的原始副本（只读语义）
│       ├── work\                         # 实验用的可变副本
│       └── snapshots\                    # 破坏性操作前的自动备份
│
├── cases\                                # ★ 归档（持久，不随工作区清空）
│   └── <case>\
│       ├── artifacts\                    # 截图、日志、导出文件
│       ├── traces\<run_id>.jsonl         # 结构化轨迹（行式，便于增量与超大文件）
│       ├── experiments\<exp_id>.json
│       ├── jobs\<job_id>.log
│       └── exports\                      # 给 Obsidian 的 markdown 等
│
├── cases.db                              # SQLite：全部实体的元数据
├── logs\
│   ├── app.log                           # 运行日志（环形）
│   └── audit.log                         # ★ 审计：谁在何时对哪个路径做了什么
└── config.toml                           # 路径、端口、默认通道、脱敏策略
```

### 两条布局原则

1. **`workspace` 可弃，`cases` 不可弃** —— 工作副本丢了能重导；归档丢了就白干。
2. **大文件不进数据库** —— trace 落 `.jsonl`（行式、可追加、可 `tail`），只有元数据进 SQLite。理由：一次高并发观测可能有百万条事件，塞进 SQLite 会让库膨胀到不可用。

---

## 四、Trace 存储格式（`.jsonl`）

每行一条事件，独立可解析。字段见 `TraceEvent`。

为什么不用一个大 JSON 数组：**追加写 + 崩溃安全 + 可流式读取**。观测中途崩了，前面的事件不能丢。

配套索引（放在 SQLite，不放在 jsonl）：

| 字段 | 用途 |
|---|---|
| run_id / file_path / line_count | 定位 |
| probe_hit_counts | 快速回答"哪个探针命中几次"（不需要扫全文件） |
| first_ts / last_ts | 时间范围查询 |

## 五、生命周期

| 阶段 | 动作 |
|---|---|
| 建案 | 创建 `workspace\<case>\`、`cases\<case>\`、写 `Case` 记录 |
| 副本 | 检材 → `workspace\<case>\<pkg>\source\`（**只读语义，任何处理都在 `work\`**） |
| 运行 | `Run` 开始 → trace 追加写 → 结束写元数据索引 |
| 破坏性操作 | 先 `snapshots\` 备份 → 记审计 |
| 归档 | 结论进 `Finding`；产物进 `artifacts\`；导出进 `exports\` |
| 清理 | **只清 `workspace`**，`cases\` 与 `cases.db` 永不自动删 |

## 六、备份、迁移与可交接

| 项 | 做法 |
|---|---|
| 单案备份 | 打包 `cases\<case>\` + `cases.db` 中该案记录 → 一个 zip |
| 迁移 | `cases.db` 带 `schema_version`；升级时按版本逐级迁移；不允许"删库重建" |
| 交接 | 导出「案卷包」：`Case` + `AppProfile` + 全部 `Finding` + trace + 产物 + 一份可读的 markdown 摘要 |
| 与其它工具互通 | `Finding` 导出 JSON；符号清单从 `apk-inspect` / jadx 导入；命令导出 PS/bash/md 三态 |

**「案卷包」这个设计是刻意的**：动态分析的痛苦之一就是"只有当时那个人知道是怎么做的"。案卷包要让接手的人**从零复现**。

## 七、配置（`config.toml`）关键项

| 键 | 默认 | 说明 |
|---|---|---|
| `workspace_root` | `D:\Project\lovelyfrida\workspace` | ★ 不给系统盘 |
| `cases_root` | `D:\Project\lovelyfrida\cases` | 同上 |
| `adb_path` | 空 → 自动探测 | 可手工指定 |
| `preferred_channel` | `auto` | `auto` / `a` / `b` / `c` |
| `frida_port` | `27042` | 被占自动换 |
| `adb_connect_timeout_s` | `15` | E-02 的硬约束 |
| `read_only_roots` | 由案件配置 | ★ 写入即拒绝 |
| `mask_secrets_in_logs` | `true` | 脱敏开关 |
| `retain_raw_log_lines` | `50000` | 环形缓冲上限 |
| `telemetry` | **恒为 false** | 不存在这个开关（不联网） |
