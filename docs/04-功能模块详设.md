# 04 · 功能模块详设

> A~H 八个功能模块 + K~M 三条横切能力。每个模块给出：职责 / 输入输出 / 关键流程 / 难点 / 关联诊断规则 / 验收。

---

## A · 环境体检（Doctor）

**职责**：在用户还没开始操作之前，把「这台机器现在能不能干活」说清楚。

| 项 | 内容 |
|---|---|
| 输入 | 用户点击「体检」（或首次启动） |
| 输出 | 一份红黄绿清单 + 每项的证据 + 可执行的修复建议 |
| 依赖 | `AdbBackend`、文件系统探测、注册表/路径枚举 |

### 检查项

| # | 检查 | 探测方式 | 通过判据 |
|:--:|---|---|---|
| 1 | 模拟器/真机是否在跑 | 进程探测 + 端口扫描 `{16384, 16385, 7555}` | 至少一个端口在监听 |
| 2 | 找到可用的 adb | 枚举候选路径（模拟器自带优先，其次 PATH） | 能执行 `adb version` |
| 3 | adb 能否连上 | `adb connect <cand>`（**15s 硬超时**） | `adb devices` 出现 `device` |
| 4 | 是否 root | `adb shell id` | 含 `uid=0(root)` |
| 5 | SELinux 模式 | `getenforce` | 记录值（`Enforcing` 时提醒 restorecon 必须做） |
| 6 | 目标 ABI | `getprop ro.product.cpu.abi` | 给出对应 frida-server 包名 |
| 7 | 本机 frida 客户端版本 | 执行 `frida --version` | 记录 |
| 8 | 三处版本是否一致 | 客户端 / 内置矩阵 / 设备端 `/data/local/tmp/frida-server` | 一致则绿；不一致给"推送匹配版"按钮 |
| 9 | 端口占用 | 检查 `27042` 是否被占 | 未占用，或给替代端口 |
| 10 | 存储与权限 | 工作区目录可写、检材路径只读可达、剩余空间 | 全部满足 |

### 难点

| 难点 | 处置 |
|---|---|
| E2：非 adbd 端口会**无限挂死** | 所有 `adb connect` 强制超时；失败立即返回，绝不阻塞 UI |
| E1：系统 adb 版本老 | 候选排序 + 显示每个候选的版本与路径，让用户看得见为什么选它 |
| 端口不确定 | 不猜：**扫描 + 逐个试 + 列出每个的结果**（试过的都留痕） |
| 假绿灯 | 第 3 项通过后**再跑一次 `adb devices` 二次确认**（对应 S5 的教训） |

### 关联诊断规则
`E-01` `E-02` `E-03` `E-04` `S-01`（见 05 文档）

### 验收
从零启动 → 体检全绿 → 用户能说出"它凭什么说连上了"（回答必须是"因为 `adb devices` 第二次确认显示 device"，而不是"因为没报错"）。

## B · 会话管理（Session Console）

**职责**：把「设备 → 应用 → frida-server → forward → attach → agent 注入」这条链托管起来，并让每一步的状态可自证。

### 关键流程

```
1. 选择目标设备（Doctor 已探明的那台）
2. 选择/导入应用档案 AppProfile（见下方）
3. 装载 APK（install -r；签名冲突自动提示 uninstall）
4. 起 frida-server：
   4.1 比对三处版本 → 不匹配则推送内置匹配版
   4.2 pkill 旧实例（清理残留 PID，记录）
   4.3 后台常驻启动（不占用户窗口）
   4.4 ss -tlnp 验证**确实在监听**
5. adb forward tcp:27042 → 设备 tcp:27042
6. attach / spawn 目标进程
7. 注入 agent → 等待 `send({t:"hello"})` 才算注入成功
```

### 应用档案（AppProfile）

一次录好，后面复用。两个真实案例：

| 字段 | `com.notevault.app` | `com.hidden.calculator` |
|---|---|---|
| APK 路径 | `…韦明辉\手机\Image\data\app\com.notevault.app-DqBtNjagKSBu5WWDeKojLg==\base.apk` | `…陈志鹏\手机\Image\data\app\com.hidden.calculator-9S1kpogUe09Avm4YD3L2vw==\base.apk` |
| uid（实测） | `10042` | `10043` |
| 数据目录 | `databases/`、`files/objectbox/private_space_db/`、`shared_prefs/` | `databases/`、`app_flutter/files/` |
| 口令文件 | `shared_prefs/notevault_prefs.xml`（明文 XML） | `app_flutter/files/password.json`（编码值） |
| 口令变换 | 无 | `[1:-2]` |
| 入口手势 | 常规登录页 | **长按右上齿轮 1.2s**（单击/双击/三连点均无反应） |
| 关键坐标（1080×1920） | — | 齿轮 (963,146)；密码框 (540,1065)；确认 (540,1265)；设置按钮 (540,1520)；输入页单框 (540,1180) + 验证 (540,1490) |
| 探针目标 | `AESUtil.hashPassword` | `net.zetetic.database.sqlcipher.SQLiteDatabase.$init` |

**「入口手势 + 坐标」是这个档案里最容易被低估的字段。** 痛点 O4 花的时间主要就在试入口上（单击/双击/三连点都不是）。

### 难点

| 难点 | 处置 |
|---|---|
| S2：frida-server 被 SIGHUP 杀 | 会话托管为常驻任务；断连检测 + 自动重启 + 事件留痕 |
| S3：旧进程残留 | 启动前强制清理，并记录清了哪些 |
| S4：forward 丢失 | 定期校验 `adb forward --list`，丢了自动补，UI 上标注"已自动恢复" |
| 注入成功 ≠ 好用 | 等 agent 的 `hello` 才算成功（原则 1） |

### 关联诊断规则
`S-01`~`S-07`

### 验收
杀掉模拟器再开机 → 会话自动恢复链路，用户不碰终端。

## C · 数据回灌（Injection Wizard）

**职责**：把检材里的 App 私有目录，安全、可验证地灌回设备。

### 关键流程（七步，逐条状态灯）

```
1. 停应用          am force-stop <pkg>
2. 空跑建档        monkey -p <pkg> -c android.intent.category.LAUNCHER 1 → sleep → force-stop
3. 建目录          逐条 mkdir -p（不依赖花括号，痛点 D4）
4. 推送文件        adb push（失败自动降级为「/data/local/tmp 中转 + su -c cp」，痛点 D2）
5. 改属主          chown -R <uid>:<uid>（uid 从 pm list packages -U 自动取，痛点 D1）
6. 刷标签          restorecon -R（Enforcing 时必做）
7. 校验            md5sum 逐文件对比（不通过则该文件红）
```

### 难点

| 难点 | 处置 |
|---|---|
| D5：App 在跑会被覆写 | 第 1 步不可跳过 |
| D6：目录属主不对 | 第 2 步不可跳过（先让 App 自己建，再覆盖内容） |
| D3：`su -c` 引号 | 命令构造层统一出「单引号 + 分号串联」形式，并给出错误范例说明 |
| D7：带登录态的 prefs 会让探针永不触发 | 第 4 步后**扫描 prefs 里的登录态键**并预警（与 O-03 联动） |
| C4：检材被写坏 | 源路径是只读根；推送前校验源文件未被修改 |

### 关联诊断规则
`D-01`~`D-07`

### 验收
灌完 4 个文件，校验全绿；且 prefs 里有登录态时给出明确预警。

## D · 探针工作台（Probe Lab）

**职责**：把「挂钩子」从写 JS 变成**填表 + 选模板**，同时把一行行日志变成结构化数据。

### 探针声明（声明式，可视化填表）

| 字段 | 取值 | 说明 |
|---|---|---|
| 目标类 | `com.notevault.app.utils.AESUtil` | 从静态分析导入的符号清单里选 |
| 目标方法 | `hashPassword` | 可填 `$init`（构造函数） |
| 重载 | 全部 / 指定签名 | 默认全部（工具自动展开 `overloads`） |
| 参数格式化 | 每个参数独立选：`string` / `byte[]hex` / `base64` / `json` / `对象字段` / `native指针` / `原样` | 解决 O1 |
| 长度上限 | 默认 128 | 超限显示 `…(+N)`，可点开（解决 O2） |
| 命中条件 | 无 / 参数匹配正则 / 返回匹配 | 用于在噪声里筛信号 |
| 动作 | 记录 / 暂停线程 / 改参数 / 改返回 / 触发快照 / 写文件 | 默认仅记录 |
| 失败策略 | 类缺失则跳过 / 报错停止 | 默认跳过但**状态灯标黄** |

### 工具自动负责的事（用户不写）

| 自动处理 | 对应痛点 |
|---|---|
| 类加载延迟注册 + 失败重试 | P2（frida 17.x 时序） |
| `overloads.forEach` 展开 | P3 |
| `$init` 构造函数 + 建成后 dump 字段 | P4 |
| 每个探针的 try/catch 与**三态上报**（已装载/类缺失/挂载失败） | P5 |
| `byte[]` hex 化（含截断） | O1 |
| 字符串/对象截断 + 计数 | O2 |
| 每次调用 `send()` 结构化事件 | O5（替代 console.log 解析） |
| 命中计数与"零命中"上报 | O3 |

### 内置模板库

| 模板 | 挂钩对象 | 产出 |
|---|---|---|
| 方法入参/返回 | 任意方法 | 调用序列 |
| 构造函数捕获 | `$init` | 建对象时收到的秘密（口令、密钥、路径） |
| 字段 dump | 对象字段（String / byte[]） | 关键字段快照 |
| SQLCipher 口令捕获 | `net.zetetic.database.sqlcipher.SQLiteDatabase` / `SQLiteConnection` / `SQLiteOpenHelper` 的 `$init` | **数据库口令明文**（本轮最有用的一招） |
| 加密出口 | `javax.crypto.Cipher` 的 `doFinal` / `init` | 算法名、模式、IV、明文/密文 |
| native 出口 | `libapp.so` / `libsqlcipher_zetetic.so` 的导出符号 | native 层调用 |
| 网络出口 | OkHttp / HttpURLConnection | 请求与响应（可与 r0capture 风格模板合并） |

### 难点

| 难点 | 处置 |
|---|---|
| 命中 0 次时容易误判"钩子坏了" | 三态分明 + 零命中诊断（O-03）：先问"是不是走了别的分支" |
| 高并发调用刷爆 UI | 事件分层 + 批量 + 虚拟滚动（02 章 L2/L3） |
| 参数是复杂对象 | 格式化器可组合（先 hex，再按 JSON 解析） |

### 关联诊断规则
`P-01`~`P-08` `O-01`~`O-05`

### 验收
用模板 + 填表完成 APK-1 的挂钩（目标是拿到 `IN='Abc123456'‖'etmLYLvSIJn2mzgC'`），**全程不写一行 JS**。

## E · 受控实验台（Experiment Bench）

**职责**：把「给自造输入 → 看它写回什么」变成可重复、可追加、可自动求差的实验。

### 实验定义

| 字段 | 说明 |
|---|---|
| 变量（自变量） | 一个被测对象：某个文件内容 / 某个 UI 输入 / 某个方法参数 |
| 观测通道（因变量） | 若干：探针入参、字段值、文件写回值、功能是否成功 |
| 输入组 | 多组取值（手工指定 + 自动生成） |
| 追加规则 | 每次可再补一组（用于**否证**刚得出的结论） |
| 输出 | 差分矩阵 + 变异度排序 + 结论候选 |

### 两个已验证的用法

**用法一 · 变换规则反推**（APK-15）

```
变量: password.json 内容
观测: ① SQLiteDatabase.$init 收到的 byte[]  ② mPassword 字段  ③ 开库成功与否
输入组: XABCDEFGHIJKLMNO / PABCDEFGHIJKLMNOII / abcdefgh / abcde / Pgs-ll20260423II
结论: [1:-2]
否证: "削 2 个尾字符"被 abcdefgh（8→5，削 3）否证 → 规则是"首 1 + 尾 2 都削"
```

**用法二 · KDF 形态与迭代次数反推**（APK-18）

```
变量: 自设口令（在 App 里设一个已知值）
观测: 库中写回的哈希
输入组: Abc123456（唯一必需的已知明文）
结论: h₁=SHA256(明文‖salt)；h_{i+1}=SHA256(hex(hᵢ))；存 hex(h₁₀₀₀₀) ⇒ 迭代 10000
自证: h_10000('Abc123456'‖salt) 的 hex 与库值逐字节相等 ✅
```

### 难点

| 难点 | 处置 |
|---|---|
| 没有「设置密码」入口 | 记录入口手势（长按/双击/三连点都试）+ 坐标点击 + 截图留痕 |
| 环境不干净（旧库残留） | 实验前自动备份并清空目标（**在工作副本上**） |
| 结论过度泛化 | 变异度排序列出**所有被支持与被否证的假说**，不只给一个 |

### 关联诊断规则
`X-01`（入口手势）`D-07`

### 验收
追加一组输入 → 矩阵更新 → 结论候选里出现一条被否证的假说。

## F · 算法还原（Crypto Reconstruct）

**职责**：给定（明文、盐、目标值），把算法**定死**，输出一份可被机器执行的规格书。

### 搜索空间（自动穷举，逐层）

| 维度 | 取值 |
|---|---|
| 哈希族 | SHA-256 / SHA-1 / MD5 / PBKDF2-SHA256/1/512 |
| 拼接顺序 | `pw‖salt` / `salt‖pw` / `pw` |
| 盐形态 | 原始字节 / base64 文本 / 连写 hex |
| 每轮输入形态 | 原始摘要 / 十六进制串 |
| 迭代结构 | 单轮 / 链式（对上一轮输出再哈希） |
| 迭代次数 | 1 ~ 1e6 扫描（先试常见值：1000/4096/10000/65536/100000/256000…） |
| 输出编码 | hex / base64 |

### 规格书输出

| 内容 | 例 |
|---|---|
| 人读描述 | `h₁ = SHA256(明文 ‖ salt)`；`h_{i+1} = SHA256(hex(hᵢ))`；存 `hex(h₁₀₀₀₀)` |
| 机器可执行 | 生成验证脚本骨架（Python） |
| 迭代数 | 10000 |
| 自证 | 本地重算与目标逐字节相等（原则 5 的第一条证据） |
| 爆破适配 | 是否有现成 hashcat mode？无则转 G 模块生成专用爆破器 |

### 难点

| 难点 | 处置 |
|---|---|
| 搜索空间爆炸 | 分层：先定族与拼接（快），再扫迭代数（用已知常见值优先）；命中即停 |
| 假命中 | 必须两条不同的 (明文,目标) 都要能重算通过；只有一条不算 |
| 编码层数多 | 明确列出"hex 了几层"，避免歧义 |

### 关联诊断规则
`C-06` `C-07`（工具缺失与自测纪律）

### 验收
输入 `Abc123456` + salt + 库中哈希 → 输出迭代数 **10000** 并给出逐字节相等的自证。

## G · 爆破编排（Brute Orchestrator）

**职责**：把规格书变成一次能跑的枚举，并**在跑之前先证明实现是对的**。

### 候选空间设计

| 方式 | 说明 |
|---|---|
| 掩码（mask） | 类 hashcat 语法：`?u?l?l?d?d?d?d?d?d`（首字母大写+两小写+6 数字） |
| 字典 | 常见口令表 + 案内词（人名、拼音、案件号、日期） |
| 规则 | 追加数字、首字母大写、leet 替换 |
| 混合 | 字典 × 掩码（如 `字典词 + 4 位数字`） |

**必须给出**：候选总数、预估耗时（基于已测速率）、磁盘占用。

### 后端选择

| 条件 | 后端 |
|---|---|
| hashcat 有对应 mode（如 `-m 1410` = `sha256($pass.$salt)`） | hashcat，生成完整命令 |
| 无对应 mode（如链式 hex SHA-256 迭代 10000） | **生成专用爆破器骨架**（C） |

### 生成的 C 骨架必须包含

| 要素 | 说明 |
|---|---|
| 链式轮优化 | 输入恒 64 字节 → 预置填充块 + `SHA256_Transform`，省掉 Update/Final 与填充计算 |
| 加速 | `gcc -O3 -march=native -fopenmp`；多核并行 |
| ★ **自测桩** | 先用已知明文跑一遍，与目标逐字节比对；**不通过就拒绝进入全量爆破** |
| 进度 | 定期打印速率与已试比例（可被 UI 读取） |
| 命中输出 | 固定格式一行（如 `HIT pwd=593476`），便于 UI 解析 |

**性能对照（实测，值得记进工具档案）**：`sprintf` 朴素版 ~200 候选/秒 → 上表方案 ~**2400 候选/秒**（4 核，约 12×）。

### 难点

| 难点 | 处置 |
|---|---|
| C-07：实现不等价 → 白跑 | 自测桩是**强制**的，不是可选项 |
| 长跑中断 | 支持断点续跑（按前缀分片）、进度持久化 |
| 结果可信度 | 命中后自动做**反向校验**（用命中值重算目标值） |

### 关联诊断规则
`C-06` `C-07`

### 验收
用 `593476` 这个真实案例跑通：生成骨架 → 自测通过 → 全量跑出 HIT → 反向校验一致。

## H · 档案台账（Evidence Ledger）

## L · 横切 · 诊断引擎（Diagnostics）

| 项 | 内容 |
|---|---|
| 规则来源 | `docs/05-诊断知识库.md`（48 条） |
| 三条触发路径 | ① 输出匹配（正则/谓词）② 状态谓词（如"探针装载成功但命中 0"）③ 定时主动探测 |
| 输出 | 诊断卡片：症状 / 真因 / 处置动作 / 出处 |
| 动作可执行 | 卡片上的处置可直接点击执行（如"adbd 非 root → 执行 `adb root` 并重连"） |
| 可关闭 | 用户可以忽略某条规则（记录忽略原因，进审计） |

**关键设计：诊断规则不替代日志，它是日志的解释层。** 原始输出永远可看（原则 2）。

## M · 横切 · 工作区与只读保护（Workspace Guard）

| 能力 | 说明 |
|---|---|
| 只读根 | 检材路径在配置里就是只读根；对它的写操作**直接拒绝**（不是警告框） |
| 强制工作副本 | 任何需要处理的检材文件，先自动复制到 `workspace\<case>\` |
| 写前校验 | 若源文件在复制后被外部修改，拒绝继续（防止"处理了一份被污染的数据"） |
| 审计 | 每次读/写都记：时间 / 路径 / 操作 / 结果 / 触发来源 |
| 隔离 | 破坏性操作（清空库、覆盖文件）只在工作副本上，且先自动备份 |
