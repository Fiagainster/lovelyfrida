# 07 · 安全、合规与工程纪律

> 这一章不是"附加条款"。动态分析工具离检材太近，纪律必须是**机制**，不是**提醒**。

---

## 一、只读第一原则（机制，不是提示）

### 1.1 一起真实事故

同一条工作流上的相邻案例：用 Docker 打开一份 MySQL 数据目录做演示时，命令里少写了 `:ro`。结果是 —— mysqld 虽然因为版本/语义冲突没启动成功，但**已经改动了检材**：重建了 `auto.cnf` 里的 UUID、碰到了 `ibdata1`、留下一个悬空的 `mysql.sock` 软链。

**失败 ≠ 无害。** 这是本节所有设计的出发点。

### 1.2 三条机制

| 机制 | 实现 |
|---|---|
| **只读根** | 案件配置里的 `read_only_roots` 是一份显式路径清单。工具在**打开文件描述符之前**就拒绝对这些路径的写操作（不是打开后报错，是根本不打开） |
| **强制工作副本** | 需要处理的任何检材文件，必须先复制到 `workspace\<case>\<pkg>\source\`。处理后端只接受工作区路径 |
| **只读语义分层** | `source\` 视为只读（来自检材）；`work\` 才是可变的；破坏性操作前自动 `snapshots\` 备份 |

### 1.3 为什么不用"警告框 + 确认"

因为警告框在**批量操作用户已经点累了**的时候会被无脑确认掉。而路径级的拒绝是**物理上做不到**，不需要用户当时清醒。

> 纪律无法依赖人在疲劳时保持清醒 —— 只能依赖它在架构上不可能。

## 二、设备侧风险

frida-server 与 adb 都是"打开的门"。工具要替用户意识到这一点。

| 风险 | 说明 | 工具对策 |
|---|---|---|
| frida-server 监听 `0.0.0.0` | 局域网内任何主机都能连上来注入 | 默认改为**只监听 `127.0.0.1`**，通过 `adb forward` 访问；如需远程才显式开启并高亮提示 |
| adb TCP 暴露 | `adb connect` 走 TCP，同网段可被扫到 | 提示使用模拟器/真机的本地回环端口；不在公网环境使用 |
| 注入目标选择错误 | 误注入系统进程可能导致设备不稳 | 目标列表里把系统进程与目标应用**分组显示**，默认只展开用户应用 |
| 设备被"污染" | 反复灌数据/装卸 APK 后，设备状态与检材不再一致 | 记录每次变更（审计）；支持"还原设备到初始状态"（脚本化清理） |

**保留证据完整性**：设备只是一次性的执行环境，**证据始终是检材文件本身**。工具要在 UI 上明确这一点，避免用户把模拟器当"证据"。

## 三、密钥与口令

动态分析会大量接触秘密（口令、盐、密钥、哈希）。这些是**成果**，也是**风险**。

| 场景 | 规则 |
|---|---|
| 界面显示 | 默认脱敏（`gs-ll****2223`），需要看时点"揭示"（有操作留痕） |
| 日志 | 默认脱敏；`mask_secrets_in_logs` 可关，但关掉时界面显式提示"当前日志含明文凭据" |
| 剪贴板 | 复制明文时提示；对高敏值（完整密钥）默认不提供"一键复制" |
| 导出档案 | 默认脱敏；需要完整值时使用**加密导出**（age），并提示这是密件 |
| 截图 | 截图前提示可能包含明文；工具在"截图位"清单里标出"此屏含明文凭据" |

**判定"什么是秘密"** 的启发式（可配置）：

- 出现完整恢复密钥格式（`[0-9]{6}(-[0-9]{6}){7}`）
- 命中已知的密钥/口令变量名（`salt`、`password_hash`、`key`、`secret`、`token`）
- 由判定的秘密派生的值（如本地重算得到的明文口令）

## 四、日志与档案脱敏

| 层 | 处理 |
|---|---|
| 原始层（L3） | 保留原样（取证需要原始），但**默认只在内存环形缓冲**，落盘需用户显式开启 |
| 结构化层（L2） | 按脱敏策略处理后再落 `traces\` |
| 导出层 | 默认全脱敏；导出时列出被脱敏的字段数量与位置，让用户自己判断要不要出完整版 |

**核心权衡**：取证要求"原始可验"，但原始数据又最容易泄露。解法是**分层 —— 默认脱敏、可显式出原始、且每次出原始都有审计**。

## 五、法律与授权边界

本工具的能力边界必须在文档最显眼处写清楚：

| 是 | 不是 |
|---|---|
| 分析**自己有权处理的**设备与应用（CTF 赛题、授权取证、自有应用） | 分析他人设备 / 未授权应用 |
| 提供技术手段，帮助使用者理解程序如何工作 | 帮助规避软件授权、破解商业保护 |
| 公开、可核对的工具行为 | 任何"隐身后门"式行为 |

### 工具主动拒绝的事

| 行为 | 处置 |
|---|---|
| 自动绕过 root 检测 / 反调试 | **不提供**。工具只会明确告诉你"这是反调试导致的"（规则 P-08），怎么做由使用者自己判断 |
| 自动绕过授权校验 | **不提供** |
| 上传任何数据到远端 | 不存在该功能 |

### 免责声明（随程序与文档分发）

> lovelyfrida 是分析工具，不具备也不提供任何越权能力。
> 使用者应确保对目标设备与应用拥有合法处置权限（自有设备、授权取证、公开赛题等）。
> 使用者对自己的使用行为负全部责任。

## 六、数据不出本机

| 项 | 承诺 |
|---|---|
| 网络请求 | **零**。不校验授权、不检查更新、不上报统计 |
| 遥测 | 不存在该开关（不是"默认关闭"，是"没有这个功能"） |
| 云端 | 无 |
| 崩溃报告 | 不外发；本地写 `logs\`，由用户自己决定是否提供 |

这条对取证场景是**硬要求**：案件数据一旦出网，性质就变了。所以它写在架构层（02 章 §1 明确"任何需要联网的组件都不使用"）。

## 七、工程纪律（针对本机环境）

| 纪律 | 具体 |
|---|---|
| **不写系统盘** | 所有持久化默认落在项目目录（`D:\Project\lovelyfrida\`）；不写 `%APPDATA%`、不写 `C:\`。理由：沿用既有的个人工作纪律 |
| 破坏性操作 | 二次确认 + **自动备份** + 审计。备份路径明确告知 |
| 批量操作 | 小批量（默认 ≤10 项/批），每批后校验，任一失败立即停 |
| 工作副本隔离 | 实验用 `work\`；`source\` 不被改动；变更前快照 |
| 幂等 | 所有连接/启动类操作可重复执行（先清残留再建立），不允许"跑第二次就坏" |
| 命令方言 | 输出按目标 shell（PowerShell / bash）出对应写法，避免"看起来能跑实际跑不通" |

## 八、审计日志（`logs\audit.log`）

每条记录：

| 字段 | 说明 |
|---|---|
| 时间 | 墙钟 + 单调 |
| 动作 | 读 / 写 / 执行命令 / 导出 / 揭示明文 |
| 目标 | 检材路径 / 设备 / 文件 |
| 结果 | 成功 / 拒绝 / 失败原因 |
| 触发来源 | 哪个视图 / 哪个模块 / 终端手敲 |
| 数据指纹 | 涉及文件的 sha256（写前/写后） |

价值有三：

1. **合规** —— 能证明"检材没有被改动"
2. **复盘** —— 出问题时知道最后一个动作是什么
3. **交接** —— 接手的人能看到前一个人做了什么

---

## 九、依赖与供应链

| 项 | 要求 |
|---|---|
| 内置二进制 | 全部记 sha256；启动时校验；来源与版本可查（adb / frida-server 各自的上游） |
| 第三方库 | 锁版本（lockfile）；不引入需要联网的依赖；定期审计已知漏洞 |
| 更新 | 只更新内置二进制与自身代码，不动用户数据（`workspace` / `cases`） |
| 可审计性 | 二进制清单随程序附带（名称、版本、sha256、下载来源），任何一项对不上就提示 |

---

## 十、本机的三条具体禁忌（从既有纪律继承）

| 禁忌 | 原因 |
|---|---|
| 不写 C 盘 | 系统盘不做数据落点（既有个人纪律） |
| 不动 `D:\System\` 等程序目录 | 那是程序自己的地盘 |
| 不碰与本案无关的目录 | 动态分析工具的手最长，边界要最紧 |

---

## 十一、给使用者的一段话（也会出现在程序首次启动页）

> 这个工具会**打开你的模拟器、往里面灌数据、挂钩子改返回值**。它做的每一件事都会留下记录。
>
> 请只用它处理你有权处理的设备与应用。也请相信它留下的记录 —— 当出问题时，那份审计日志是你唯一能证明"我没动过检材"的东西。
