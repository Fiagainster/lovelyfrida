## 一、背景

原规划（04-D）的探针工作台只覆盖取证场景的 Java 声明式探针。调研结论：真实 frida 工作流 = 附加 →
**探索**（类/方法/符号枚举搜索）→ **批量 trace**（frida-trace 式 glob 挂桩）→ 精挂 → 观测 → 数据操作
（内存搜索/heap/主动调用）→ 改环境 → 沉淀（脚本固化）。原规划只覆盖第 4 步。

## 二、核心架构决策

**把"探针工作台"从功能降级为实例。** M2 的 agent 重构为通用调试底座（参照 Luma Agent/core 裁剪到
Android Java+native），声明式探针成为底座上的一种 instrument：

```
core agent（每进程一个常驻脚本实例）
├── env        进程指纹（sha256 身份）、Frida/Java 运行时状态
├── enum       Java 类/方法枚举搜索（enumerateMethods 通配）、模块/导出/符号分页查询（agent 侧过滤排序）
├── memory     read/write、Memory.scan（带 limit）、dump 流式回传
├── threads    快照/寄存器、add/remove 微批上报（setImmediate 合帧）
├── repl       evaluate（let/const→var 提升）、complete（原型链补全，上限 256）
├── value      PackedValue 值编码：22 tag + blob 分离，深度 3 + DepthLimit/Circular 哨兵
├── console    console 猴子补丁 + 分级 send
├── resolver   AnchorJSON 判别联合（javaMethod / moduleOffset / moduleExport / absolute），
│              hook 目标一律存锚点不存裸地址
└── hooks      hook 登记表：attach/replace 全登记，updateConfig 原位 diff 复用，dispose 可逆

instruments（动态装载的模块，FeatureSchema 自描述配置 + 7 种 widget 输出）
├── 声明式探针（04-D 的 7 模板，成为 instrument 之一）
├── frida-trace 式 glob 批量挂桩（生成可编辑桩 + 热重载）
└── 用户脚本（Interceptor 代理包装：执行瞬间登记脚本内全部 hook → 可逆卸载；codeshare 导入）
```

**"浏览即动作"枢纽**：所有地址/指针/方法值统一挂右键菜单（复制 / 打开内存 / 挂 hook），
把探索器、内存视图、trace、REPL 粘合成一个整体（照搬 Luma AddressMenuItems）。

## 三、新增一等公民视图（03 视图集从 6 个扩到 8 个）

| 视图 | 职责 | 关键交互 |
|---|---|---|
| 探索器 Explorer | Java 类/方法搜索（`*password*` 通配）、模块/导出/符号分页浏览、堆实例搜索（Java.choose）、线程/寄存器 | 行右键 → 地址菜单（一键挂桩/加探针/复制） |
| REPL 台 | frida REPL（复用底部终端抽屉，从 adb shell 切换 frida 模式） | Notebook cell 持久化、补全、历史、值树渲染 |
| 脚本库 Scripts | TS/JS 脚本项目（frida-compile 打包）、模板再编辑 + 热重载、codeshare 导入（哈希审查）、运行/卸载 | 编辑器 Monaco + 错误内联 + 一键运行 |

（时间轴/差分/拓扑/档案按 03 原设计不变。）

## 六、验收增补

- **U2b（新）**：attach 后不写一行 JS，用探索器搜索 `*cipher*` 定位方法并一键挂桩，时间轴看到参数。
- **U2c（新）**：从脚本库运行任意用户脚本（含第三方 codeshare 源码粘贴），卸载后目标行为完全恢复（可逆性）。
- 原 U1~U10 不变。
