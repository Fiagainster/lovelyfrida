# 01 · 问题域与设计原则

> 这个工具不是凭空设计的。它是把一次真实动态分析里踩过的 **33 个坑**固化成产品能力。

---

## 一、场景还原：这 33 个坑是怎么来的

2026 盘古石杯决赛第二轮。两个灰产 App 需要「动态补齐」——静态分析已经拿到了类名和方法名，但**参数到底是什么形状**只有跑起来才知道：

| App | 包名 | 要问出来的问题 | 结论 |
|---|---|---|---|
| 私密笔记（韦明辉） | `com.notevault.app` | 用户密码哈希吃什么盐、怎么拼 | `Base64(SHA-256(明文‖salt))` → 爆破得 `Wei123123` |
| 假计算器（陈志鹏） | `com.hidden.calculator` | 数据库口令怎么从文件算出来 | `password.json[1:-2]` |
| 同上 | 同上 | 用户密码哈希迭代几次 | `10000` |
| 同上 | 同上 | 用户密码本身是什么 | 自写 C 爆破器 → `593476` |

整条链路在命令行里手工走通，最终 25 道 APK 题全部拿下。**但过程极其依赖"我记得住每个坑"** —— 下面这 33 条，就是当时必须靠记忆和试错跨过的坎。

## 二、痛点台账（33 条）

**记号**：`⚙` 已被现有脚本固化 ｜ `⚠` 反复踩过 ｜ `☠` 踩了会损坏检材

### E · 环境（4 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| E1 | 系统 `adb` 版本老，连不上模拟器 | 改用模拟器自带的那份 `adb.exe` | 自动枚举候选 adb（模拟器自带优先），显示每份的版本与来源路径 |
| E2 | ⚠ 不知道该连哪个端口：`16384` / `16385` / `7555` 都可能；连 `5555` **无限挂死** | 靠 `netstat` 手工找监听端口 | 端口集合扫描 + **连接硬超时 15s** + 失败即换，绝不无限等 |
| E3 | WSL 的宿主机 IP 每次重启都变（`172.27.48.1` 之类） | 写脚本动态探测（`resolv.conf` nameserver → 默认路由网关兜底） | 多候选地址自动探测；连不上时列出所有试过的地址与结果 |
| E4 | `adb devices` 显示 `offline`（模拟器刚起来） | `disconnect` → 等 2 秒 → 重连，最多重试 5 次 | 内建「offline 自愈」重试曲线，并把重试次数显示在状态灯旁 |

### S · 会话（5 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| S1 | ☠ `failed to connect to remote frida-server`（客户端与 server 版本不一致） | 手工比对两处版本号，下载对应 `frida-server-<v>-android-x86_64` | **三处版本联动检查**（本机客户端 / 内置矩阵 / 设备端），一键推送匹配版 |
| S2 | ⚠ frida-server 是**前台进程**，`adb shell` 通道一断就被 SIGHUP 杀 —— 所以必须**独占一个窗口，不能关** | 单开一个 PowerShell 窗口挂着不动 | 会话托管：后台常驻 + 断连自动重启 + 状态灯；用户不必"守着窗口" |
| S3 | 设备端残留旧 frida-server 进程（旧 PID 不会自己死） | 起新的之前 `pkill -f frida-server` | 启动前自动清理残留，并记录清理了哪些 PID |
| S4 | 不 `adb forward` 就连不上 `127.0.0.1:27042` | 手工一条 forward | forward 作为会话的一部分自动建立，并在拓扑视图里画出来 |
| S5 | 无法确认 server 真的在监听 | `ss -tlnp \| grep :27042` 单独验证 | 「声称已启动」与「实测在监听」分开表示，避免假绿灯 |

### P · 注入（5 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| P1 | 类名/方法名靠猜（`com.notevault.app.utils.AESUtil.hashPassword`） | 先静态分析拿到候选，再逐个试 | 从 jadx/APK 结果导入候选符号，做"可勾选的目标清单" |
| P2 | ⚠ frida 17.x 时序下类还没加载，hook 直接失败 | 整个 `Java.perform` 包在 `setTimeout(..., 3000)` 里 | **自动延迟注册 + 失败重试**，用户不写 `setTimeout` |
| P3 | 同名方法多个重载，直接 `impl` 会报歧义 | 遍历 `.overloads.forEach` 逐个挂 | 探针声明只写方法名，重载展开由工具生成 |
| P4 | 构造函数不是普通方法，要挂 `$init` | 手工写 `C.$init.overloads.forEach` | 「构造函数」作为一等探针类型；对象建成后自动 dump 字段 |
| P5 | 类不存在时 hook 静默跳过（`try/catch` 吞了错误） | 靠 `skip xxx: not found` 日志才发现 | 每个探针独立状态：**已装载 / 类缺失 / 挂载失败**，三态分明 |

### O · 观测（5 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| O1 | `byte[]` 直接打印是 `[B@1a2b3c`，毫无信息 | 手工写 hex 化函数（并截断到 64 字节） | 参数格式化器内置：`string / byte[] hex / base64 / json / 对象字段 / native 指针` |
| O2 | 大对象 `String(a)` 打出来几十 KB，日志炸开 | 手工 `.slice(0, 120)` | 格式化器带长度上限；超限显示 `…(+N)`，可点开 |
| O3 | ⚠ **探针装上了，但一次调用都没有** | 判断是 App 带着登录态直接进了主页，没走登录分支 | 「零命中」诊断：命中 0 次时主动列出可疑原因与验证动作 |
| O4 | 隐藏入口：**长按右上齿轮 1.2 秒**才弹设置页（单击/双击/三连点都没反应）；Flutter 界面无可枚举控件 | 靠截图 + 坐标硬点（(963,146) 齿轮、(540,1065) 密码框……） | 记录「入口手势」到应用档案；提供坐标点击 + 截图留痕 |
| O5 | 算法还原靠肉眼读 `IN=... OUT=...` 一行行反推 | 人工比对、人工猜公式 | **结构化 Trace**：入参/返回分列成表，可筛选、可对比、可导出 |

### D · 数据回灌（7 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| D1 | 回灌要 4 步：`mkdir` → `push` → `chown <uid>` → `restorecon`；**少一步 App 就读不到** | 手工四步，uid 从 `pm list packages -U` 抄（10042 / 10043） | 回灌向导：自动查 uid、自动建目录、四步全跑、**末步哈希校验** |
| D2 | `push` 到 `/data/data/` 报 `Permission denied` | 走 `/data/local/tmp` 中转再用 `su -c cp` | 权限失败自动降级为「中转 + su」路径，不用用户自己想到 |
| D3 | ⚠ `su -c "…"` 被拆包，报 `su: invalid option -- a` | 发现**只能用单引号**：`su -c '命令1; 命令2'` | 命令构造层统一处理引号，给出可直接复制的正确形式 |
| D4 | ⚠ PowerShell 没有 bash 的花括号展开（`a/{b,c}`），旧 bash 脚本不能直接抄 | 一条条改写成独立命令 | 命令渲染按目标 shell 输出（PS / bash 两套模板），不生成跑不通的形式 |
| D5 | App 在跑的时候灌数据会被覆写 | 灌之前 `am force-stop` | 回灌前强制停应用，写进流程不可跳过 |
| D6 | `mkdir` 出来的目录属主不对 | 先空跑一次让 App 自己建目录结构 | 「空跑建档」作为回灌流程第一步，自动执行 |
| D7 | prefs 里带登录态时 App 跳过登录页 → 探针永不触发 | 手工删掉登录态相关的键 | 回灌时**扫描登录态键**并预警（与 O3 联动） |

### C · 加密库（7 条）

| ID | 症状 | 当时怎么处置 | 工具该怎么做 |
|:--:|---|---|---|
| C1 | DB Browser 打开报 `file is not a database`，**连密码框都不弹** | 读文件头发现不是 `SQLite format 3` | 文件识别器：读头 16 字节判定库类型（明文 SQLite / SQLCipher / bbolt / ObjectBox），给出结论而不是让用户猜 |
| C2 | `sqlcipher` 命令行用同一口令报 `encrypted-or-not-a-database` | 改用 python 绑定 `sqlcipher3` 才开 | 内建正确的开库路径（python 绑定），并把 CLI 这条死路写进诊断库 |
| C3 | SQLCipher 兼容档要试（`cipher_compatibility` 4/3 + `kdf_iter` + `hmac_algorithm`） | 写循环穷举 4 种组合 | 开库向导：组合穷举 + 报告哪一档命中 |
| C4 | ☠ 库被写一次就重新加密 = **破坏检材** | 事后才发现失败启动动了 `auto.cnf`（同类教训） | 只读挂载 + 强制工作副本；对检材路径的写操作直接拒绝 |
| C5 | ⚠ 口令存放位置因 App 而异，且可能是**编码值** | notevault 在 `shared_prefs/*.xml` 明文；hidden.calculator 在 `app_flutter/files/password.json` 且真值 = `[1:-2]` | 应用档案记「口令文件位置 + 变换规则」；找不到时给出两个已知形态的排查顺序 |
| C6 | 链式十六进制 SHA-256，**通用爆破器没有这个模式** | 自己写 C：迭代 10000 轮，链式轮输入恒 64 字节 → 预置填充块 + `SHA256_Transform`；性能 200 → **2400 候选/秒** | 算法规格书 → 生成专用爆破器骨架；记录性能对照 |
| C7 | ☠ 自己写的爆破器如果实现不等价，跑完也白跑 | **先用已知明文自测**（`h_10000('Abc123456'‖salt)` 与库值逐字节相等）才开跑 | 生成骨架时**强制附带自测桩**，自测不过不允许进入全量爆破 |

## 三、六条设计原则

### 原则 1 · 状态可见 > 自动完成

自动化会把状态藏起来。而动态分析最怕的就是**假绿灯** —— 以为连上了、以为钩子挂上了、以为程序走了登录分支。

所以：**每一个「已经完成」的断言，都必须有独立的实测证据**。声称 server 已启动 ≠ 实测在监听（S5）；探针已装载 ≠ 被调用过（O3）。UI 上这两件事分开显示。

### 原则 2 · 三层下钻

任何可视化结果都能往下走三层：

```
视图层（我能看懂）
  └─ 命令层（等价 adb / frida 命令，可一键复制）
       └─ 原始层（未经处理的 stdout / stderr 全文）
```

理由：用户要的不只是答案，是**"我怎么自己得到这个答案"**。工具应该是最好的老师，不是最厚的黑箱。

### 原则 3 · 只读是默认值，不是选项

检材路径在工具里就是**只读根**：

- 从检材读取的任何文件，自动复制到工作区后才参与处理
- 对检材路径的写操作被直接拒绝（不是警告框，是拒绝）
- 所有写操作的落点只有一处：`D:\Project\lovelyfrida\workspace\`

依据：这一轮的同类教训是**漏了 `:ro`，一次失败启动就改了检材的 `auto.cnf`**（C4）。纪律不能靠人记得。

### 原则 4 · 受控实验是第一公民

动态分析里最稀缺的东西不是算力，是**已知明文**。

只要 App 提供「设置密码 / 新建 / 导入」这类入口，就等于白送一次已知明文实验：给一个**自造值**，看它**写回什么**，规则就自己浮出来了。

两个实测案例：

| 实验 | 输入 | 观测 | 推出的规则 |
|---|---|---|---|
| APK-15 | `password.json` 改成 `XABCDEFGHIJKLMNO`（16 字节） | 挂 `SQLiteDatabase.$init` 抓到 `byte[]"ABCDEFGHIJKLM"` | 真口令 = 文件内容 `[1:-2]` |
| APK-18 | 自设口令 `Abc123456` | 读回库里的哈希 | `h₁=SHA256(明文‖salt)`、`h_{i+1}=SHA256(hex(hᵢ))`、存 `hex(h₁₀₀₀₀)` ⇒ 迭代 **10000** |

所以工具要有专门的「受控实验台」：**输入变量组 × 观测通道 → 差分矩阵**，并自动高亮"只有它不同"的那一列。

### 原则 5 · 双证据闭环

任何结论必须两条独立路径都对上：

1. **数学自证**：本地重算一遍，与目标值逐字节相等
2. **真机复现**：把结果灌回 App，功能真的走通（本例：输 `593476` → 进入「笔记」列表，5 条笔记全显示）

只有一条 → 标低置信；两条都有 → 才算闭环。这条直接决定档案里「置信度」字段怎么填。

### 原则 6 · 版本三处一致

frida 生态最容易翻车的地方是版本（S1）。三处必须一致：

| 处 | 当时的值 |
|---|---|
| 本机 frida 客户端 | `16.7.19`（`D:\System\Python\Scripts\frida.exe`） |
| 内置 frida-server | `16.7.19-android-x86_64` |
| 设备端已装 | 同上 |

工具要能**同时显示这三处并指出不一致**，而不是等连接失败再回头查。另外版本还影响时序（17.x 类加载更慢，需要 P2 的延迟注册），这个差异也要写进版本矩阵。

## 四、目标用户与使用场景

| 用户 | 场景 | 工具提供什么 |
|---|---|---|
| 取证人员（本工具的主用户） | 拿到检材，要回答"这个 App 的数据怎么算出来的" | 全链路 + 只读保护 + 可归档的证据链 |
| CTF 选手 | 移动方向题，卡在"参数形状不明" | 快速受控实验 + 自造爆破器 |
| 教学/笔记作者 | 要把一次动态分析写成能复现的教程 | **命令录制回放** + 一键导出带截图位的 markdown |

第三个场景不是附赠 —— 它是本工具和"写在笔记本里的一次性脚本"的根本区别。

## 五、与现有工具的关系

| 工具 | 它擅长 | lovelyfrida 与它的关系 |
|---|---|---|
| `frida` / `frida-trace` CLI | 一切底层能力 | **不是替代**。lovelyfrida 有「原始终端」视图直连它，且每次可视化操作都给出等价命令 |
| objection | 免 root 的常见操作（ssl pinning、root 检测绕过） | 互补。objection 解决"已知需求的批处理"，lovelyfrida 解决"未知目标的探索与还原" |
| r0capture | 抓包神器 | 互补。它可以作为一个「探针模板包」被导入 |
| MobSF | 静态+动态扫描报告 | **取向相反**。MobSF 要自动化结论，lovelyfrida 要可见过程 |
| Frida CodeShare | 现成脚本 | 作为**探针模板库**的来源之一，导入后仍需绑定到具体目标 |

一句话：**现有工具都在替你干活；lovelyfrida 在陪你把活干明白。**

## 六、本工具箱边界的自觉

工具能力有天花板，文档要说清在哪：

- **不解决"类名未知"** —— 那是静态分析（jadx / apktool）的活。本工具接受它导入的符号清单。
- **不解决"加密算法在 native 里"** —— 那需要 `libapp.so` 层的 hook 与反汇编配合。工具提供 native 探针接口，但不做反汇编器。
- **不解决"设备不可 root"** —— 授权与环境准备是用户的责任。
- **不保证"一次就中"** —— 它保证的是**失败时你知道为什么失败**（第五份文档解决的就是这件事）。
